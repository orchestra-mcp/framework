# flow-pack (`orchestra-mcp/pack-flow`)

**Version**: v2.3.0 (released 2026-03-19)
**License**: MIT
**Location**: `packs/pack-flow/`
**Applies to**: All stacks (`*`)

## What is it?

`pack-flow` is the FLOW methodology pack for Orchestra MCP. It provides a complete decision-centric product development framework covering Discovery (learning) and Outcome (shipping) cycles, with gates, kill conditions, experiments, and team rituals.

> "The mode determines which artifacts, gates, and rituals apply."

## Three-Layer Architecture

| Layer | What | Always Active? |
|-------|------|----------------|
| 1 | CLAUDE.md ambient rules (7 rules) | Yes — on every interaction |
| 2 | 18 interactive `/flow-*` skills | On demand |
| 3 | Persistent memory (`.flow/` directory) | Accumulates per project |

## 7 Ambient Rules (embedded in CLAUDE.md)

These run passively on every interaction — no skill invocation needed.

1. **Mode Awareness** — Discovery (learning) vs. Outcome (shipping). Ask: "Is the primary risk building the wrong thing, or failing to ship the right thing?"
2. **Kill Conditions** — Pre-committed, specific, measurable, timebound. Written BEFORE attachment forms. Default is kill when triggered.
3. **Spine Trace** — Every cycle traces: Vision → Strategy → Bet → Cycle. If it doesn't trace, it doesn't enter the system.
4. **WIP Limits** — Solo: 1–2 | Small (3–8): 2–3 | Medium (10–20): 4–5 | Large (25+): 6–8
5. **Gate Enforcement** — D1–D3 (Discovery gates), O1–O5 (Outcome gates). Never skip gates.
6. **Learning Capture** — Archive every completed or killed cycle. Every kill = a success (saved resources).
7. **Tempo Awareness** — Speed-agnostic. Never assume 2–4 week sprints — ask about the team's Tempo.

## Gates

| Gate | Stage | Checks |
|------|-------|--------|
| D1 | Discovery | Brief ready to pursue? |
| D2 | Discovery | Experiment designed properly? |
| D3 | Discovery | Enough evidence to switch modes? |
| O1 | Outcome | Bet worth pursuing? |
| O2 | Outcome | SPEC ready for Build Contract? |
| O3 | Outcome | Build Contract complete? |
| O4 | Outcome | Observability in place? |
| O5 | Outcome | Kill, Merge, or Continue? |
