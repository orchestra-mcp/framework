# Orchestra MCP Notes System

The notes system is a standalone plugin (`libs/plugin-tools-notes/`) providing 8 MCP tools for full note management with project scoping, full-text search, tagging, and pinning.

---

## 8 MCP Tools

### CRUD Operations
| Tool | Description |
|------|-------------|
| `create_note` | Create a note with title, body, optional tags/icon/color. Returns auto-generated ID (`note-XXXXXX`) |
| `get_note` | Retrieve a note by ID with formatted metadata header |
| `update_note` | Update body and optionally title/tags/icon/color |
| `delete_note` | Soft-delete (sets `deleted: true`; file not physically removed) |

### List & Search
| Tool | Description |
|------|-------------|
| `list_notes` | List all notes, optionally filtered by project, tag, or pinned status. Returns markdown table |
| `search_notes` | Case-insensitive substring search on title AND body content |

### Metadata Operations
| Tool | Description |
|------|-------------|
| `pin_note` | Pin or unpin a note (boolean toggle) |
| `tag_note` | Add or remove tags with duplicate prevention |

---

## Note Data Model

**Storage Format:** Markdown files with YAML frontmatter (via Protobuf Struct metadata)

**Note ID:** `note-XXXXXX` (6 random hex characters)

### Metadata Fields (YAML Frontmatter)

| Field | Type | Description |
|-------|------|-------------|
| `id` | string | Note ID (e.g., `note-a1b2c3`) |
| `title` | string | Note title (required) |
| `body` | string | Markdown content (required, stored as file body) |
| `pinned` | bool | Default `false` |
| `deleted` | bool | Default `false` (soft delete flag) |
| `created_at` | string | ISO 8601 timestamp |
| `updated_at` | string | ISO 8601 timestamp (updated on every change) |
| `tags` | []string | Optional, empty if not set |
| `icon` | string | Icon name (optional, e.g., `lightbulb`) |
| `color` | string | Color label (optional, e.g., `yellow`) |

## Storage Backend

### File Paths
```
{projectSlug}/notes/{noteID}.md
```

### Project Scoping
- Each project has its own notes directory
- Default project slug: `.global` (for unscoped notes)
- Project scoping is opt-in via `project_id` parameter

### Storage Protocol
Uses the orchestrator's storage plugin protocol (Protobuf-based):
- `StorageRead` — Read note with metadata + body + version
- `StorageWrite` — Write note with metadata + body + expected version (optimistic locking)
- `StorageDelete` — Delete note file
- `StorageList` — List all notes in a project by pattern matching

### Concurrency Control
- Optimistic locking via version numbers
- `WriteNote` expects version to match current; fails on mismatch
- Version auto-incremented on each write

## Plugin Architecture

### File Structure
```
libs/plugin-tools-notes/
├── cmd/main.go                    # Plugin binary entry point
├── export.go                      # In-process registration (Register function)
├── internal/
│   ├── plugin.go                  # ToolsPlugin struct + RegisterTools
│   ├── storage/
│   │   └── client.go              # DataStorage abstraction (8 methods)
│   └── tools/
│       ├── create_note.go
│       ├── get_note.go
│       ├── update_note.go
│       ├── delete_note.go
│       ├── list_notes.go
│       ├── search_notes.go
│       ├── pin_note.go
│       ├── tag_note.go
│       └── tools_test.go          # 159 assertions
├── go.mod
└── orchestra.json                 # Plugin manifest
```

### Registration Flow
1. `Register()` in `export.go` is called by the in-process router
2. Creates `DataStorage` with `StorageClient` (orchestrator connection)
3. Instantiates `ToolsPlugin` with the storage reference
4. `RegisterTools()` wires all 8 handlers to the plugin builder

### Tool Handler Pattern
- Each tool exports a **Schema function** (returns JSON Schema as `*structpb.Struct`)
- Each tool exports a **handler function** (`func(ctx, *pluginv1.ToolRequest) (*pluginv1.ToolResponse, error)`)
- Handlers use the `helpers` package for validation, type extraction, and error formatting

## Key Implementation Details

### Soft Delete
- `delete_note` sets `deleted: true` flag — file is not physically removed
- All list/search operations skip notes with `deleted: true`
- No explicit undelete (would require manual metadata update)

### Tag Management (`tag_note`)
- Supports `add` and `remove` actions
- Deduplicates on add
- Tag removal filters out specified tags, preserves others

### Search (`search_notes`)
- Case-insensitive substring matching
- Searches both title and body
- Results returned as markdown table

### List Filtering (`list_notes`)
- 3 composable filters: `project_id`, `tag`, `pinned` (AND logic)
- Deleted notes automatically excluded

### Error Types
| Error | Cause |
|-------|-------|
| `validation_error` | Missing/invalid required fields |
| `not_found` | Note doesn't exist or is deleted |
| `storage_error` | Underlying storage operation failed |
| `internal_error` | Metadata serialization failure |
